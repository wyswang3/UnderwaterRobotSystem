# 香橙派当前实验操作员使用说明

## 文档状态

- 状态：Authoritative
- 说明：给现场操作员使用的中文顺序卡，覆盖开机、脚本赋权、Python 解释器、虚拟环境、车端启动、上位机启动和最短排障。

## 0. 适用目录与当前口径

目录约定：

- `<UnderwaterRobotSystem repo root>`：OrangePi 上的车端系统仓根目录
- `<UnderWaterRobotGCS repo root>`：上位机上的 GCS 仓根目录

当前默认口径固定为：

1. 车端默认主路径：`control_only`
2. 车端推荐入口：`bash tools/supervisor/run_local_teleop_smoke.sh up-real`
3. 上位机主入口：`ROV_IP=<OrangePi_IP> bash tools/supervisor/run_local_teleop_smoke.sh teleop`
4. GUI 只做观察，不替代 TUI
5. 调试模式默认关闭，只有显式传参或设置环境变量时才打开

## 1. 从开机到打开终端

电脑开机后按固定顺序做：

1. 登录系统，进入桌面。
2. 打开终端。
3. 推荐准备 3 个终端窗口：
   - 终端 1：车端控制侧
   - 终端 2：上位机 TUI
   - 终端 3：上位机 GUI 或只读观察
4. 先确认当前机器上需要的仓库已经部署到位：

```bash
pwd
ls
```

OrangePi 上至少要能进入 `<UnderwaterRobotSystem repo root>`；上位机上至少要能进入 `<UnderWaterRobotGCS repo root>`。如果仓库目录不存在，不要继续启动，先确认部署位置。

## 2. 第一次使用前先赋权

如果是新环境、刚拷贝脚本、或者脚本提示 `Permission denied`，先执行一次：

```bash
cd <UnderwaterRobotSystem repo root>
chmod +x tools/supervisor/run_local_teleop_smoke.sh

cd <UnderWaterRobotGCS repo root>
chmod +x scripts/run_tui.sh
chmod +x scripts/run_gui.sh
```

如果要手动使用进入环境脚本，也可以一并赋权：

```bash
cd <UnderWaterRobotGCS repo root>
chmod +x scripts/enter_gcs_env.sh

cd <UnderwaterRobotSystem repo root>
chmod +x enter_py311.sh
chmod +x tools/supervisor/enter_supervisor_env.sh
```

## 3. Python 版本、解释器目录和环境脚本

### 3.1 当前推荐 Python 版本

当前工作区实测通过的 Python 版本是：

```text
Python 3.11.11
```

如果需要现场确认，执行：

```bash
python3 --version
```

### 3.2 启动脚本怎么选解释器

当前脚本都已经内置解释器选择逻辑。

GCS 脚本优先顺序：

1. `UROGCS_PYTHON_BIN`
2. `UnderWaterRobotGCS/.venv/bin/python`
3. `python3`
4. `python`

车端 helper / supervisor 脚本优先顺序：

1. `URO_SUPERVISOR_PYTHON_BIN`
2. `UnderwaterRobotSystem/UnderwaterRobotSystem/.venv/bin/python`
3. `$HOME/venvs/py311/bin/python`
4. `python3`
5. `python`

这意味着：

1. 平时不用手动改解释器目录，直接运行脚本即可。
2. 如果现场必须显式指定解释器，先导出环境变量再运行脚本。

例如：

```bash
export UROGCS_PYTHON_BIN=/path/to/python3
export URO_SUPERVISOR_PYTHON_BIN=/path/to/python3
```

### 3.3 如何激活当前工作区环境

如果只是正常启动，直接跑启动脚本即可，不强制要求手动激活虚拟环境。

如果要手动进入环境，按下面方式执行。

GCS 环境：

```bash
cd <UnderWaterRobotGCS repo root>
source scripts/enter_gcs_env.sh
```

车端 supervisor 环境：

```bash
cd <UnderwaterRobotSystem repo root>
source ./enter_py311.sh
source tools/supervisor/enter_supervisor_env.sh
```

说明：

1. 如果仓库里有 `.venv`，脚本会优先进入 `.venv`。
2. OrangePi 侧的 `source ./enter_py311.sh` 会优先激活 `$HOME/venvs/py311`，并把该解释器导出给 supervisor/helper。
3. 如果仓库里没有 `.venv`，且 `$HOME/venvs/py311` 也不存在，脚本才继续使用当前系统里的 `python3`。

### 3.4 代码部署后先重新编译

如果刚把代码同步到 OrangePi，或者刚 `git pull` / 切分支 / 替换源码目录，不要直接执行启动脚本，先重新编译受影响仓。

最小规则：

1. 只改了文档仓 `<UnderwaterRobotSystem repo root>`，不需要编译。
2. 改了 `pwm_control_program`、`gcs_server`、`nav_viewd`、gateway 或控制链代码，要重新编译 `<OrangePi_STM32_for_ROV repo root>`。
3. 改了 `uwnav_navd` 或导航 runtime 代码，要重新编译 `<Underwater-robot-navigation repo root>/nav_core`。
4. 改了 ROS2 bridge，才需要额外执行 `colcon build`。

控制 / gateway / PWM 仓重新编译：

```bash
cd <OrangePi_STM32_for_ROV repo root>
cmake -S . -B build
cmake --build build -j4
```

导航 runtime 重新编译：

```bash
cd <Underwater-robot-navigation repo root>
cmake -S nav_core -B nav_core/build
cmake --build nav_core/build --target uwnav_navd -j4
```

如果只是想稳妥一点，最简单的口径就是：OrangePi 侧运行代码一旦有更新，先把对应仓重新编译，再执行 `up-real` / `up`。

ROS2 bridge 只在需要时编译：

```bash
cd <OrangePi_STM32_for_ROV repo root>/ros2_bridge
PATH=/usr/bin:/bin:$PATH . /opt/ros/humble/setup.bash
colcon build --event-handlers console_direct+ \
  --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3 -DPYTHON_EXECUTABLE=/usr/bin/python3
```

## 4. 车端启动控制程序

### 4.1 推荐主路径：真实 STM32 输出

终端 1 执行：

```bash
cd <UnderwaterRobotSystem repo root on the OrangePi>
bash tools/supervisor/run_local_teleop_smoke.sh up-real
```

这是当前推荐的实机控制启动方式。它会自动完成：

1. `usb_serial_snapshot.py --json`
2. `device-scan --json`
3. `startup-profiles --json`
4. `phase0_supervisor.py preflight --profile control_only`
5. `phase0_supervisor.py start --profile control_only --detach --real-pwm`
6. `status`

### 4.2 如果只想安全联调，不真正打到 STM32

终端 1 执行：

```bash
cd <UnderwaterRobotSystem repo root on the OrangePi>
bash tools/supervisor/run_local_teleop_smoke.sh up
```

这时 `pwm_backend=dummy`，表示：

1. 控制链能跑
2. `pwm_control_program` 能算 PWM
3. 但不会真正发包到 STM32

### 4.3 推荐状态与排障命令

车端常用命令固定为：

```bash
cd <UnderwaterRobotSystem repo root on the OrangePi>

bash tools/supervisor/run_local_teleop_smoke.sh doctor
bash tools/supervisor/run_local_teleop_smoke.sh status
bash tools/supervisor/run_local_teleop_smoke.sh restart
bash tools/supervisor/run_local_teleop_smoke.sh restart-real
bash tools/supervisor/run_local_teleop_smoke.sh down
```

判读顺序固定为：

1. 先看 `doctor`
2. 再看 `status`
3. 如果仍异常，再看 `last_fault_summary.txt` 和 `child_logs/`

### 4.4 车端最重要的检查项

至少确认：

1. `pwm_control_program` 是 `running`
2. `gcs_server` 是 `running`
3. 实机联调时 `pwm_backend=stm32`
4. 实机联调时 `real_pwm=1`
5. `profile=control_only`
6. `operator_lane=teleop_primary`

如果看到 `pwm_backend=dummy`，不要把“界面有反馈”误判成“STM32 已经收到 PWM”。

## 5. 上位机启动

### 5.1 推荐主路径：从 helper 打开 TUI

终端 2 执行：

```bash
cd <UnderWaterRobotGCS repo root on the upper computer>
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_tui.sh --preflight-only
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_tui.sh
```

如果 OrangePi IP 不是 `192.168.2.24`，把上面 IP 改成现场真实地址。

### 5.2 只打开只读观察 GUI

终端 3 执行：

```bash
cd <UnderWaterRobotGCS repo root on the upper computer>
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_gui.sh --preflight-only
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_gui.sh
```

### 5.3 如果要直接进入 GCS 仓库启动

TUI：

```bash
cd <UnderWaterRobotGCS repo root>
bash scripts/run_tui.sh --preflight-only
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_tui.sh
```

GUI：

```bash
cd <UnderWaterRobotGCS repo root>
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_gui.sh --preflight-only
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_gui.sh
```

## 6. 如何显式打开调试模式

当前调试默认关闭。

只有下面两种方式才会打开会话调试：

```bash
UROGCS_SESSION_DEBUG=1 UROGCS_ROV_IP=192.168.2.24 bash scripts/run_tui.sh
UROGCS_SESSION_DEBUG=1 UROGCS_ROV_IP=192.168.2.24 bash scripts/run_gui.sh
```

或者：

```bash
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_tui.sh --debug-session
UROGCS_ROV_IP=192.168.2.24 bash scripts/run_gui.sh --debug-session
```

正常作业时不要默认开调试。

## 7. 车端手动原始命令

如果 helper 不可用，再按原始命令手动启动。

预检查：

```bash
cd <UnderwaterRobotSystem repo root on the OrangePi>
python3 tools/supervisor/phase0_supervisor.py preflight \
  --profile control_only \
  --startup-profile auto \
  --real-pwm
```

启动：

```bash
cd <UnderwaterRobotSystem repo root on the OrangePi>
python3 tools/supervisor/phase0_supervisor.py start \
  --profile control_only \
  --startup-profile auto \
  --detach \
  --real-pwm
```

查看状态：

```bash
python3 tools/supervisor/phase0_supervisor.py status --json
```

停止：

```bash
python3 tools/supervisor/phase0_supervisor.py stop --timeout-s 5.0
python3 tools/supervisor/phase0_supervisor.py bundle --json
```

## 8. 最短排障

### 8.1 脚本报没有执行权限

重新赋权：

```bash
cd <UnderWaterRobotGCS repo root>
chmod +x scripts/run_tui.sh
chmod +x scripts/run_gui.sh

cd <UnderwaterRobotSystem repo root>
chmod +x enter_py311.sh
chmod +x tools/supervisor/run_local_teleop_smoke.sh
```

### 8.2 提示 `python interpreter not found`

按顺序处理：

1. 先执行 `python3 --version`
2. 在 OrangePi 侧执行 `source ./enter_py311.sh` 或 `source tools/supervisor/enter_supervisor_env.sh`
3. 在上位机侧执行 `source scripts/enter_gcs_env.sh`
4. 必要时显式设置：

```bash
export UROGCS_PYTHON_BIN=/path/to/python3
export URO_SUPERVISOR_PYTHON_BIN=/path/to/python3
```

### 8.3 14550 端口占用

先执行：

```bash
cd <UnderwaterRobotSystem repo root on the OrangePi>
bash tools/supervisor/run_local_teleop_smoke.sh doctor
bash tools/supervisor/run_local_teleop_smoke.sh down
pgrep -af "gcs_server|phase0_supervisor.py|pwm_control_program"
```

### 8.4 TUI/GUI 能连上，但车没动作

先看车端 `status --json`，重点确认：

1. `pwm_backend=stm32`
2. `real_pwm=1`
3. `pwm_control_program` 没有落到 dummy backend

如果这里是 `dummy`，说明你当前只是在本机联调。
